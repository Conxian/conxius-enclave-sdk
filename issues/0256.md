# [ALIGNMENT] Update control_model_adapter.rs to mirror Core v0.3.0 48-chain taxonomy

**Issue #256** | CLOSED | Created: 2026-07-30 | Updated: 2026-07-30

## Problem

`src/protocol/control_model_adapter.rs` mirrors Core types to avoid a circular dependency (Core optionally depends on SDK). However, the mirror is stale:

```rust
// Current (stale):
pub enum CoreChainFamily {
    BitcoinUtxo,  // Bitcoin, Stacks, Liquid, Lightning, Babylon ← WRONG
    Evm,          // Bob, Mezo, Citrea, Botanix, ...
    CosmosIbc, SolanaSvm, Move, Substrate  // 6 total
}
```

Core v0.3.0 has expanded to **17 families, 48 chains** aligned with bitcoinlayers.org.

### Stale mappings
| Chain | SDK Family | Core v0.3.0 Family |
|---|---|---|
| Stacks | BitcoinUtxo | **Anchor** |
| Liquid | BitcoinUtxo | **Federation** |
| Babylon | BitcoinUtxo | **BPoS** |
| Lightning | BitcoinUtxo | BitcoinUtxo ✅ |

### Missing families (11 new)
Statechain, Ark, BPoS, Federation, MergeMined, Anchor, Rollup, AltRollup, AltLayer1, Csv, Hybrid

### Missing chains (25 new)
Spark, MercuryLayer, Second, Arkade, Rootstock, Alpen, Arch, Midl, Nomic, SideProtocol, Alkanes, Bevm, Bitlayer, Bsquared, Core, Corn, Flashnet, Fractal, Goat, Hemi, InternetComputer, Merlin, Rgb, Rollux, Starknet

## Proposed Resolution

1. Expand `CoreChain` enum from 23→48 variants
2. Expand `CoreChainFamily` enum from 6→17 variants
3. Update `CoreChain::family()` mapping per Core v0.3.0
4. Update `Chain::to_core_chain()` and `chain_to_network()` mappings
5. Ensure wire-compatible serde names match Core
