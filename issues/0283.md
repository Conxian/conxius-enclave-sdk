# P2: Gate FROST DKG ceremonies behind enclave attestation verification

**Issue #283** | CLOSED | Created: 2026-08-05 | Updated: 2026-08-05

### Summary
FROST DKG ceremonies (keygen, signing) must be gated behind attestation verification. Only enclaves with valid attestation evidence (Nitro, KeyMint/StrongBox) should be allowed to participate in value-bearing FROST ceremonies.

### Background
- FROST DKG is implemented (#265, PR #264)
- FrostSigningContext bridges raw bytes ↔ crypto (#266, PR #275)
- Attestation infrastructure exists but is not wired to FROST ceremony entry points
- Without this gate, any caller can participate in DKG rounds regardless of hardware trust tier

### Scope
1. Add attestation check to  entrypoint
2. Add attestation check to signing round entrypoints
3. Reject non-attested participants with  error
4. Wire to TrustTier model (T3 Nitro, T4 Android StrongBox)
5. Add tests: attested passes, non-attested rejected

### Dependencies
- #240 (attestation roots, collateral, revocation)
- #241 (Android KeyMint/StrongBox qualification)
- #242 (AWS Nitro attestation)

### Priority
**P2** — gates FROST ceremonies until attestation infrastructure is operational. Does not block development (can use dev-mode bypass) but must be in place before production signing.
