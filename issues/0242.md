# [P0] Qualify AWS Nitro attestation and KMS secret-release boundary

**Issue #242** | OPEN | Created: 2026-07-22 | Updated: 2026-08-30

Parent: [SDK umbrella #195](https://github.com/Conxian/conxius-enclave-sdk/issues/195)

Linear umbrella: [CON-1512](https://linear.app/conxian-labs/issue/CON-1512/p0-enforce-hardware-backed-signing-and-mandatory-attestation-for-value-bearing)

This focused tracker does not close #195 or CON-1512 by itself.

## Goal

First production server/cloud TEE for measured workload authorization and, only where explicitly qualified, enclave-held protocol signing.

## Boundary

Nitro attestation proves workload measurement/identity; it does not replace an HSM or automatically prove protocol-key custody. Long-lived enterprise keys remain in HSM/KMS where supported; enclave-local secp256k1/Schnorr requires separate evidence/review.

## Acceptance checklist

- [ ] Parse/verify CBOR/COSE Nitro attestation documents and AWS PKI.
- [ ] Pin PCR/image/workload policy and reject debug/all-zero PCRs.
- [ ] Bind nonce, enclave public key, operation digest, key ID, purpose, policy version, expiry, and replay identity.
- [ ] Limit KMS release to approved measurements, workload identity, and environment.
- [ ] Fail closed for invalid/expired roots/certificates, revocation/collateral refresh failures, and provider outages.
- [ ] Produce real Nitro/vsock/KMS deployment evidence and negative vectors.
- [ ] Prove secret material never reaches application, CI, browser/WASM, or agent layers.
- [ ] Qualify exact signing algorithms/custody claims rather than inferring them from TEE attestation.
- [ ] Link exact release, SBOM/provenance, and independent review evidence.
