# [P0] secp256k1 0.32.0-beta.2 is yanked — breaks downstream lockfile resolution

**Issue #320** | CLOSED | Created: 2026-08-29 | Updated: 2026-08-30

## Problem

`Cargo.toml` pins `secp256k1 = { version = "0.32.0-beta.2", ... }` (line 62). This version is **yanked** from crates.io, so any fresh dependency resolution (`cargo generate-lockfile`, `cargo add`, or a downstream crate consuming this SDK) fails with:

```
error: failed to select a version for the requirement `secp256k1 = "^0.32.0-beta.2"`
  version 0.32.0-beta.2 is yanked
```

## Impact

- Breaks `conxian-nexus` CI `audit` job (which runs `cargo generate-lockfile`), blocking merge of conxian-nexus PR #250.
- Affects every downstream consumer doing a fresh resolve (both the v2.0.15 git tag and current v2.0.16).
- `secp256k1` is a hard (non-optional) dependency, so it is not gated behind a feature.

## Fix

Bump `secp256k1` off the yanked beta to a non-yanked release (`0.33.0` latest, or `0.31.1`). Must re-verify the FROST path: `frost-secp256k1-tr` (v3.0.0) must stay compatible with the chosen `secp256k1` version.

## Verification

- `cargo update -p secp256k1 --precise <version>` then `cargo generate-lockfile` succeeds.
- Full `cargo test --locked` + clippy clean; `frost` feature tests still pass.
