# P0: FROST execution context — bridge opaque envelopes to raw ZF FROST bytes

**Issue #266** | CLOSED | Created: 2026-08-03 | Updated: 2026-08-03

## Summary

The boundary types in frost.rs use `FrostOpaqueEnvelope` (digest + length) for structural validation. The `frost_crypto.rs` module works with raw ZF FROST byte serialization. We need an execution context that bridges the two.

## Problem

- `FrostSignatureShare` wraps a `FrostOpaqueEnvelope` (digest only), not raw share bytes
- `frost_crypto::aggregate()` needs raw `BTreeMap<Vec<u8>, Vec<u8>>` (id → share bytes)
- The bridge requires an execution context that holds the actual crypto material

## Proposed solution

Add `FrostSigningContext` (behind `frost-crypto` feature) that:
1. Accepts `FrostKeyPackage` (with verifying_key bytes)
2. For each `FrostSignatureShare`, maps opaque envelope digest → raw share bytes
3. Calls `frost_crypto::aggregate()` with resolved raw bytes
4. Returns hex-encoded Schnorr signature
