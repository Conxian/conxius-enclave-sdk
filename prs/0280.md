# fix: serde support for large byte arrays + CI stabilization

**PR #280** | CLOSED | Author: botshelomokoka | Created: 2026-08-03 | Merged: 2026-08-03

Branch: `fix/serde-big-arrays` → `main`

Fixes the Rust CI (Linting + Rust Tests) failures on main.

### Root cause
Rust 1.97 removed the blanket serde `Serialize`/`Deserialize` impl for arrays with more than 32 elements. This affects `[u8; 48]` (compressed G₁) and `[u8; 96]` (compressed G₂) in the BitVM2 Groth16 proof structures.

### Changes
- **New**: `serde_big_array` module with generic serde helpers for `[u8; 48]` and `[u8; 96]`
- Updated `BitVm2Groth16Proof` and `BitVm2Groth16VerificationKey` to use explicit serde attributes
- Added missing `HashMap` import in `frost.rs` (Rust 2024 edition requires explicit imports)
- Fixed `secp256k1::from_byte_array` deref in `dlc.rs` (expects owned `[u8; 32]`, received `&[u8; 32]`)
- Applied `cargo fmt` across all source files

### Testing
- `cargo check` passes cleanly on Rust 1.97
- Test compilation failures (ARK unwrap, WASM) are pre-existing and unrelated
