# feat: require canonical six-proof authorization for settlement rails

**PR #244** | CLOSED | Author: charliecreates[bot] | Created: 2026-07-22 | Merged: 2026-07-22

Branch: `con-1512-canonical-rail-authorization` → `main`

## Summary

Implements the highest-ranked bounded CON-1512 slice: the canonical six-proof authorization from merged PR #239 is now the required precondition for value-bearing settlement rail authorization and dispatch.

Candidate rationale: P0 value-bearing risk and hardware-attestation containment have the highest impact; this is a bounded additive bridge with no provider enablement, reuses the canonical operation/policy/replay/clock invariants, preserves legacy public types for compatibility, and adds direct rail/production containment evidence.

## What changed

- `src/enclave/proofs.rs` is authoritative for settlement authorization:
  - exact six-proof production policy: server identity, user authorization, phone/device attestation, TEE attestation, FIDO2/WebAuthn assertion, and TPM quote;
  - exact operation digest, purpose, audience, nonce/challenge, policy digest, proof-set/envelope digest, freshness, trusted-clock rollback, and replay binding;
  - proof-set digest is included in the typed signing operation binding before provider signing.
- `RailProxy` now requires `ProofBoundValueBearingAuthorization`, rechecks the exact six-proof policy and bindings, enforces freshness/rollback, and reserves replay before downstream rail execution.
- `OpportunityDispatcher::execute_with_proofs` provides the explicit canonical route. The normal no-proof swap route rejects before provider key lookup; the production route stops at the intentionally unavailable verifier registry.
- Legacy `src/enclave/proof.rs` `ProofSetPolicy`/`VerifiedProofSet` types and compatibility fields remain available, but cannot satisfy the canonical rail precondition or provide a conversion bypass.
- Positive proof verifiers/fixtures remain test-only; production verifier routes remain `Unsupported`/unavailable. Raw production signature dispatch and software/default providers remain fail-closed.
- Updated the proof policy specification, production checklist, capability matrix, and machine-readable evidence without claiming hardware or production support.
