# fix(release): add User-Agent to crates.io artifact download

**PR #326** | CLOSED | Author: botshelomokoka | Created: 2026-08-30 | Merged: 2026-08-30

Branch: `fix/release-verify-user-agent` → `main`

## Summary

Fixes the release pipeline's crates.io artifact verification, which has been **failing every tag push since v2.0.16** and silently blocking GitHub Release creation.

## Root cause

`verify-registry-artifact.sh` downloads the just-published `.crate` from crates.io via `curl` **without a `User-Agent` header**. crates.io returns **HTTP 403** for requests lacking a User-Agent, so the download always failed → "crates.io artifact did not match the attested crate" → `Create GitHub Release` was skipped.

Note: `cargo publish` itself *succeeds* (the crate is on crates.io), so the failure was purely in the post-publish verification — which is why v2.0.16 and v2.0.17 are published but have no GitHub Release.

## Fix

Add an identifying `User-Agent` to the download `curl`:

```
curl --fail --silent --show-error --location --proto '=https' --tlsv1.2 \
  --user-agent "conxius-enclave-sdk release verification (https://github.com/Conxian/conxius-enclave-sdk)" \
  "$registry_url" --output "$download_path"
```

## Verification

- Without User-Agent: crates.io returns **403**.
- With User-Agent: **HTTP 200**, 943,457 bytes downloaded for `v2.0.17`; SHA-256 computed correctly.
- `bash -n` syntax check passes.

## Follow-up (after merge)

Re-run `release-strict` in **recovery** mode for `v2.0.16` and `v2.0.17` to backfill the two missing GitHub Releases without re-publishing.
