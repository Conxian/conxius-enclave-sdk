# feat: FrostSigningContext — bridge FROST envelopes to real ZF FROST v3.0.0 crypto (#266)

**PR #275** | CLOSED | Author: botshelomokoka | Created: 2026-08-03 | Merged: 2026-08-03

Branch: `feat/frost-signing-context` → `main`

## Summary

Closes #266 by adding `FrostSigningContext` — an execution context that bridges the `FrostManager` opaque envelope layer to the `frost_crypto.rs` real ZF FROST v3.0.0 crypto backend.

## Problem

- `frost_crypto.rs` has working DKG + signing (PR #264 merged, 458/458 tests)
- `FrostManager` still returns `ProtocolUnsupported` for all methods
- The gap: opaque envelopes (digest-only) can't carry raw crypto bytes

## Solution

`FrostSigningContext` stores raw ZF FROST bytes keyed by SHA-256 digest. Opaque envelopes carry the digest; the context resolves digests to raw bytes on demand.

### API

| Method | Description |
|--------|-------------|
| `generate_key_package(min, max)` | Real ZF FROST trusted dealer keygen → `FrostKeyPackage` |
| `create_nonces(key_digest)` | Nonce + commitment generation for a participant |
| `create_signing_package(msg, digs)` | Build signing package from commitment digests |
| `create_signature_share(key, nonce, msg)` | Individual signature share |
| `aggregate_signatures(kp, shares)` | Combine shares → hex-encoded Schnorr signature |

### Tests

3 new tests (behind `#[cfg(all(test, feature = "frost-crypto"))]`):
- `e2e_keygen_sign_aggregate_2_of_3` — full lifecycle
- `rejects_unknown_digest_on_lookup` — error on bogus digest
- `rejects_aggregate_without_signing_package` — error on missing session

### Architecture

```
FrostSigningContext (NEW)  ←  bridges the gap
    ├── stores raw bytes keyed by SHA-256 digest
    ├── calls frost_crypto.rs for real crypto
    └── uses FrostManager types for boundary validation

FrostManager (existing)    ←  unchanged
    └── structural validation only

frost_crypto.rs (existing) ←  unchanged
    └── ZF FROST v3.0.0 real crypto
```
