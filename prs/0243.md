# feat(enclave): add Android authorization evidence boundary

**PR #243** | CLOSED | Author: charliecreates[bot] | Created: 2026-07-22 | Merged: 2026-07-22

Branch: `charlie/con-1544-android-evidence-boundary` → `main`

## Summary

This PR delivers the first production-honest SDK slice for CON-1544 / GitHub #241: a bounded Android KeyMint/StrongBox authorization evidence boundary without pretending that Android qualification is complete.

### Delivered

- Added `src/enclave/android_authorization.rs` with versioned, bounded, `serde(deny_unknown_fields)` request/evidence types for:
  - `StrongBoxRequired` and `AndroidTeeAllowed` policies.
  - Reported StrongBox, Android TEE, and software tiers.
  - Key identity/public-key digest, package/signing-certificate identity, nonce/challenge, operation digest, key purpose, and algorithm.
  - Bounded DER certificate chains and bounded opaque Play Integrity evidence.
  - Freshness/future-skew validation and redacted debug output.
- Added deterministic, domain-separated request binding over the complete request context plus DER-chain and Play Integrity evidence digests.
- Bound `ProofKind::Phone` to the explicit route `conxian.proof.phone.android-keymint.unavailable.v1` while preserving the production registry's fail-closed `Unavailable` behavior.
- Added focused positive canonicalization and negative structural/security tests.

### Explicit non-claims and blockers

This PR does **not** qualify Android KeyMint, StrongBox, Android TEE, or Play Integrity for production. Synthetic fixtures cannot produce a production-positive authorization, `VerifiedProofSet`, or accepted `AttestationLevel::StrongBox`.

The production route remains unavailable pending:

- Real Android KeyMint ASN.1 authorization-list parsing and verification.
- Trusted Android roots, collateral, validity/revocation/status handling.
- Server-side Play Integrity verification bound to the exact request.
- Durable provider-neutral replay/consume-once support from [#240](https://github.com/Conxian/conxius-enclave-sdk/issues/240).
- Real-device qualification, release provenance/SBOM, and independent review.

No roots, credentials, private keys, provider secrets, or fake production provider were added. `src/enclave/android_strongbox.rs` remains a software/development simulator boundary.
