# fix(release): gate GitHub Release on registry evidence

**PR #228** | CLOSED | Author: charliecreates[bot] | Created: 2026-07-21 | Merged: 2026-07-21

Branch: `charlie/con-1516-release-evidence` → `main`

## Summary

- Keep `.github/workflows/release-strict.yml` as the only publisher and GitHub Release creator, with an explicit manual path for either publishing an absent version or recovering an already-published matching registry artifact.
- Require the reusable full-history Gitleaks workflow on release tag paths before release evidence and publication can proceed.
- Retain a durable evidence bundle containing the crate, checksum, lockfile hash, SPDX SBOM, source commit/ref, workflow run identity, and sanitized provenance verification identity.
- After `cargo publish`, download the crates.io crate with bounded retry/backoff, compare its SHA-256 digest with the packaged/attested crate, retain a machine-readable comparison record, and make GitHub Release creation depend on that successful verification.
- Correct current release documentation so repository controls are distinguished from live tag/registry evidence; #199 and #202 remain open.

## Safety boundary

- No Git tag was created.
- No GitHub Release was created.
- Nothing was published to crates.io or any other registry.
- No publishing credentials were required or used.
- This PR adds repository controls only; it does not claim issue #199 or independent release acceptance issue #202 is resolved.
