# fix(wasm): add runtime evidence and fail-closed constructors

**PR #229** | CLOSED | Author: charliecreates[bot] | Created: 2026-07-21 | Merged: 2026-07-21

Branch: `fix/200-wasm-runtime-evidence` → `main`

## Summary

- Harden the generated WASM boundary so unsupported providers and runtimes fail with stable typed errors instead of wrapping an inert `UnavailableEnclave`.
- Normalize malformed boundary input to `INVALID_INPUT` and keep simulator-only constructors behind the development feature gate.
- Add executable runtime evidence for generated Node, Node worker, bundler-package, browser, and real Web Worker paths, with reproducible artifact hashes and toolchain/runtime metadata.
- Document the evidence limits: all capability lanes remain `Unsupported` until approved provider, hardware attestation, production policy, and release evidence exist.

## Security boundary

The generated APIs expose opaque handles, public data, approved results, and typed error codes only. The default artifact does not expose private keys, seeds, signing material, reversible secret tokens, or simulator constructors. Unsupported construction is fail-closed with `UNSUPPORTED_PROVIDER`; malformed input is reported as `INVALID_INPUT`; unsupported runtime/provider paths do not silently fall back to software or mocks.

## Runtime evidence

`scripts/run_wasm_runtime_evidence.sh` builds fresh `nodejs`, `bundler`, and `web` artifacts with pinned `wasm-pack`/Rust settings, records artifact sizes and SHA-256 hashes, and runs:

- Node package initialization and boundary assertions.
- Node `worker_threads` execution.
- Bundler ESM import using Node's WebAssembly module support.
- Browser execution served over HTTP with Playwright/Chromium.
- A real module Web Worker loading the generated web artifact.

The harness covers initialization, typed unsupported failures, malformed input, lifecycle/repeated calls, retry behavior, and absence of secret-bearing readback properties. The local committed-head run passed with 16 assertions in each Node, worker, bundler, browser-main, and browser-worker lane. The CI workflow installs the pinned browser, requires the browser lane, and uploads the evidence directory with the recorded toolchain and artifact metadata.

## Remaining production blockers

This PR adds runtime/artifact evidence only; it does not establish provider, hardware, attestation, release provenance, or production support. No approved opaque-key provider adapter is registered, so the relevant capability lanes remain `Unsupported` in `docs/architecture/WASM_SUPPORT_MATRIX.md`. Simulator/mock paths remain development-only and cannot satisfy production attestation policy.
