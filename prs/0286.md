# feat(frost): attestation-gated FROST ceremonies — closes #283

**PR #286** | CLOSED | Author: botshelomokoka | Created: 2026-08-05 | Merged: 2026-08-05

Branch: `feat/frost-attestation-gating` → `main`

## Summary
Gates all FROST DKG and signing operations behind an optional enclave attestation policy. This is the P2 cryptography enhancement from #283.

## Changes
- `FrostSigningContext` now has `attestation_policy` and `last_attestation` fields
- `set_attestation_policy()` — configure attestation requirements
- `set_attestation()` — record a validated `DeviceIntegrityReport`
- `clear_attestation()` — reset after key rotation or session expiry
- `requires_attestation()` — check if policy exists but no attestation provided
- `check_attestation()` — validates report timestamp against policy max_age/max_future_skew

## Gated Operations
All 5 crypto methods now call `check_attestation()` at entry:
- `generate_key_package()`
- `create_nonces()`
- `create_signing_package()`
- `create_signature_share()`
- `aggregate_signatures()`

## Backward Compatibility
When no attestation policy is set (the default), all operations proceed as before. This is a purely additive change — no breaking change for existing consumers.
